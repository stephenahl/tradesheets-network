16 — PERFORMANCE MEASUREMENT AND OWNER REPORTING
=================================================

Reuse existing task/attempt/event/usage records. Do not build an elaborate monitoring platform before the existing records fail to answer practical questions. [F07]

Important metric definitions:
Attempts = every provider request attempt, including failures/interruption.
Completed output = returned deliverable; not necessarily accepted/correct.
Accepted work = independently reviewed deliverable meeting predeclared criteria.
Success rate = accepted / reviewed terminal tasks; report blocked/unreviewed separately.
First-pass quality = accepted without substantive rework / reviewed outputs.
Reliability = successful on-time workflow runs / expected scheduled runs, including missed runs/downtime.
Efficiency = accepted useful outcomes per dollar, plus elapsed time and rework.
Owner burden = required interventions, manual minutes, and approval latency.
Safety/data quality = rejected forbidden actions, stale-data halts, duplicate suppression, unknown charges/labels.
Financial contribution = real attributable net result for a business and period, not a model assertion.

Minimum run/report record:
Period; business/workflow/task IDs; agent; source/model/config version; attempted/completed/reviewed/accepted status; last event and health observation; tests/reviewer; artifact references; tokens; estimated/accounted/reserved/unknown cost; errors; remaining authorization; next action or stop reason.

Keep financial accounting disciplined:
- Count failed/retried/planning/review calls and relevant tools.
- Reconcile with provider billing rather than treating estimates as invoices.
- Include actual hosting, data, acquisition, fulfillment, refund, and maintenance expense as appropriate.
- Allocate shared expense once using a documented method.
- Count business revenue/profit once at business level; list agent contributions without giving every agent the same whole profit.
- Report time savings as time unless a defensible financial conversion exists.
- Keep cash flow, accounting profit, realized trading P&L, and unrealized marks distinct.
- Missing data stays unknown, not zero.

Reporting cadence is a target: daily exceptions, weekly accepted work/cost/outcome/owner-burden review, periodic workflow retain/improve/pause/retire decisions. Notification delivery itself is not yet configured merely because this cadence is recommended.

A useful owner report says what was built, where it is, what was actually tested, what failed, what it cost, whether it was installed, and which exact decision needs Stephen. Avoid celebratory summaries that replace evidence.
